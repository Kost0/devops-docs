# Эксплуатация

## Штатная публикация
1. Убедитесь, что проверка `pylint` в Pull Request успешна.
2. Выполните слияние в `main`.
3. Откройте Actions → Publish documentation.
4. Дождитесь успеха заданий `build` и `deploy`.
5. Откройте URL из окружения `github-pages` и проверьте главную страницу.

## Ручной перезапуск

Для повторной публикации используйте Actions → Publish documentation → Run
workflow.
Пустой коммит для этой цели не требуется.

## Диагностика

Сначала определите отказавший этап: CI, сборка сайта, загрузка артефакта или
публикация.

Затем читайте журнал конкретного шага. Повторный запуск без анализа причины не
считается устранением инцидента.

# Журнал типовых инцидентов

| Инцидент | Наблюдаемый признак | Первичный источник диагностики |
|---|---|---|
| Неиспользуемая переменная | Красная проверка `pylint` в PR | Журнал шага Static
analysis |
| Недостаточные права публикации | `build` успешен, `deploy` не получает OIDCтокен | Журнал `deploy-pages` и блок `permissions` |
| Битая ссылка | `mkdocs build --strict` завершается ошибкой | Журнал шага Build
documentation |
| Старая версия после успешного деплоя | Зелёный workflow, прежнее содержимое в
браузере | URL окружения, время публикации, кэш браузера |

## Правило разбора

В разборе указываются симптом, затронутый компонент, доказательство из журнала,
причина, исправление и проверка восстановления. Ответ «перезапустил и заработало»
без установления причины неполон.
